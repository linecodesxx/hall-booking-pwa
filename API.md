# Hall Booking API

Бэкенд приложения для бронирования помещений.  
Стек: **Express 4 + SQLite (sql.js) + JWT + WebSocket**

Базовый URL: `http://localhost:3001/api`  
WebSocket: `ws://localhost:3001/ws?token=<JWT>`

---

## Аутентификация

Все запросы, кроме `/api/auth/login`, требуют заголовок:

```
Authorization: Bearer <JWT-токен>
```

Токен выдаётся на 30 дней при входе.

---

## Эндпоинты

### 🔐 Auth

#### `POST /api/auth/login`

Вход или регистрация. Если пользователь уже существует — проверяет пароль.  
Для первого входа (как нового пользователя, так и существующего без пароля) требуется инвайт-код.

**Тело запроса:**

| Поле | Тип | Обязательный | Описание |
|------|-----|-------------|----------|
| `name` | string | да | Имя пользователя |
| `password` | string | да | Пароль |
| `code` | string | нет | Инвайт-код (`ADMIN_INVITE_CODE` → admin, `USER_INVITE_CODE` → user) |

**Ответ `200`:**

```json
{
  "token": "eyJ...",
  "user": { "id": 1, "name": "Иван", "role": "admin" }
}
```

**Ошибки:** `400` — нет имени/пароля/инвайт-кода, `401` — неверный пароль

---

#### `GET /api/auth/me`

Информация о текущем пользователе.

**Ответ `200`:**

```json
{
  "user": { "id": 1, "name": "Иван", "role": "admin" }
}
```

**Ошибки:** `401` — нет/просрочен токен, `404` — пользователь не найден

### 🏛️ Halls (помещения)

#### `GET /api/halls`

Список активных помещений (мягкое удаление: `is_active = 0`).

**Ответ `200`:**

```json
{
  "halls": [
    { "id": 1, "name": "Конференц-зал", "description": "На 50 человек", "color": "#2563eb", "is_active": 1 }
  ]
}
```

---

#### `POST /api/halls`

Создать помещение. Только **admin**.

**Тело запроса:**

| Поле | Тип | Обязательный | Описание |
|------|-----|-------------|----------|
| `name` | string | да | Название помещения |
| `description` | string | нет | Описание |
| `color` | string | нет | Цвет в HEX (из палитры). Если не указан — назначается автоматически |

**Ответ `201`:**

```json
{
  "hall": { "id": 2, "name": "Переговорка", "description": "", "color": "#20a36b", "is_active": 1 }
}
```

**WebSocket:** событие `hall.created`

---

#### `DELETE /api/halls/:id`

Деактивировать помещение (is_active = 0). Только **admin**.

**Ответ `200`:**

```json
{ "ok": true }
```

**WebSocket:** событие `hall.deactivated`

---

### 📅 Bookings (брони)

#### `GET /api/bookings`

Список броней.  
Админ видит все; обычный пользователь — только свои.

**Query-параметры (все опциональны):**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `status` | string | `pending`, `approved`, `cancelled`, `rejected` |
| `date` | string | `YYYY-MM-DD` |
| `hall_id` | number | ID помещения |

**Ответ `200`:**

```json
{
  "bookings": [
    {
      "id": 1,
      "hall_id": 1,
      "hall_name": "Конференц-зал",
      "hall_color": "#2563eb",
      "title": "Совещание",
      "comment": "Нужен проектор",
      "admin_comment": null,
      "date": "2026-06-11",
      "start_time": "10:00",
      "end_time": "11:00",
      "status": "approved",
      "user_id": 1,
      "user_name": "Иван",
      "created_at": "2026-06-10 12:00:00",
      "updated_at": null
    }
  ]
}
```

> Поля `user_id`, `user_name`, `comment`, `admin_comment`, `created_at`, `updated_at` скрыты для обычных пользователей, если бронь не их.

---

#### `GET /api/bookings/schedule`

Расписание на конкретную дату. Возвращает залы с привязанными бронями (статусы `pending` и `approved`).

**Query:**

| Параметр | Тип | Обязательный |
|----------|-----|-------------|
| `date` | string | да, `YYYY-MM-DD` |

**Ответ `200`:**

```json
{
  "date": "2026-06-11",
  "halls": [
    {
      "id": 1,
      "name": "Конференц-зал",
      "description": "",
      "color": "#2563eb",
      "is_active": 1,
      "bookings": [
        {
          "id": 1,
          "hall_id": 1,
          "title": "Совещание",
          "start_time": "10:00",
          "end_time": "11:00",
          "status": "approved"
        }
      ]
    }
  ]
}
```

---

#### `POST /api/bookings`

Создать бронь.  
Админ получает статус `approved` сразу. Обычный пользователь — `pending`.

**Тело запроса:**

| Поле | Тип | Обязательный | Описание |
|------|-----|-------------|----------|
| `hall_id` | number | да | ID помещения |
| `date` | string | да | `YYYY-MM-DD` |
| `start_time` | string | да | `HH:MM` |
| `end_time` | string | да | `HH:MM` |
| `title` | string | да | Название мероприятия |
| `comment` | string | нет | Комментарий |

**Ответ `201`:**

```json
{
  "booking": { "...": "..." },
  "warning": "На это время уже есть заявка, ожидающая подтверждения..."
}
```

> `warning` появляется, если есть пересекающиеся `pending`-заявки.

**Ошибки:** `400` — валидация, `409` — пересечение с approved-бронью  
**WebSocket:** событие `booking.created`

---

#### `PATCH /api/bookings/:id/cancel`

Отменить бронь.  
Свой пользователь отменяет только свою; админ — любую.  
Уже отменённые/отклонённые брони повторно отменить нельзя.

**Ответ `200`:**

```json
{ "booking": { "...": "..." } }
```

**Ошибки:** `403` — чужая бронь, `400` — уже отменена  
**WebSocket:** событие `booking.cancelled`

---

#### `PATCH /api/bookings/:id/approve`

Подтвердить бронь. Только **admin**.  
Перед подтверждением проверяет конфликты.

**Тело запроса:**

| Поле | Тип | Описание |
|------|-----|----------|
| `admin_comment` | string | Комментарий администратора |

**Ответ `200`:**

```json
{ "booking": { "...": "..." } }
```

**Ошибки:** `409` — пересечение с approved-бронью  
**WebSocket:** событие `booking.updated`

---

#### `PATCH /api/bookings/:id/reject`

Отклонить бронь. Только **admin**.

**Тело запроса:**

| Поле | Тип | Описание |
|------|-----|----------|
| `admin_comment` | string | Комментарий администратора |

**Ответ `200`:**

```json
{ "booking": { "...": "..." } }
```

**WebSocket:** событие `booking.updated`

---

#### `PATCH /api/bookings/:id`

Редактировать бронь. Только **admin**.  
Можно менять любое подмножество полей.

**Тело запроса:**

| Поле | Тип | Описание |
|------|-----|----------|
| `title` | string | Название |
| `comment` | string | Комментарий |
| `admin_comment` | string | Комментарий администратора |
| `date` | string | `YYYY-MM-DD` |
| `hall_id` | number | ID помещения |
| `start_time` | string | `HH:MM` |
| `end_time` | string | `HH:MM` |

**Ответ `200`:**

```json
{ "booking": { "...": "..." } }
```

**WebSocket:** событие `booking.updated`

### 👥 Users (пользователи)

#### `GET /api/users`

Список всех пользователей. Только **admin**.

**Ответ `200`:**

```json
{
  "users": [
    { "id": 1, "name": "Иван", "role": "admin", "created_at": "...", "last_login_at": "..." }
  ]
}
```

---

#### `DELETE /api/users/:id`

Удалить пользователя. Только **admin**.  
Нельзя удалить последнего администратора.

**Ответ `200`:**

```json
{ "ok": true }
```

**Ошибки:** `400` — попытка удалить последнего админа

---

### 🌐 WebSocket

**Подключение:** `ws://localhost:3001/ws?token=<JWT>`

**События (от сервера к клиенту):**

| Событие | Данные | Когда происходит |
|---------|--------|----------------|
| `booking.created` | `{ type, booking }` | Создана новая бронь |
| `booking.updated` | `{ type, booking }` | Бронь подтверждена/отклонена/отредактирована |
| `booking.cancelled` | `{ type, booking }` | Бронь отменена |
| `hall.created` | `{ type, hall }` | Создано новое помещение |
| `hall.deactivated` | `{ type, id }` | Помещение деактивировано |

При ошибке авторизации — закрытие соединения с кодом `4001`.

---

## Коды ошибок

| Код | Описание |
|-----|----------|
| `400` | Ошибка валидации (неверные/отсутствующие поля) |
| `401` | Не авторизован / сессия истекла |
| `403` | Недостаточно прав |
| `404` | Ресурс не найден |
| `409` | Конфликт (пересечение броней) |
| `500` | Внутренняя ошибка сервера |

Формат ошибки:

```json
{
  "error": "Текст ошибки",
  "conflicts": []
}
```
